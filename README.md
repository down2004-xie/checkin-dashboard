# checkin-dashboard

**每日签到聚合站 + 电子日记 + 本地工具集**，一个纯静态的三视图 Web 应用。把每天要签到的网站收拢成卡片网格，点卡片跳转签到、回来打勾；每天发生的事（实习日志、会议记录、随手记）记在日记里；另附一套完全在浏览器里运行的实用工具（图片处理、格式转换、文本统计等）。无后端、无数据库、无账号系统，数据只存在浏览器本地。

线上地址：<https://ai0.tyu.me/>（旧地址 <https://down2004-xie.github.io/checkin-dashboard/> 会自动跳转过来）

## 功能特性

### 签到看板

- **进度环**：今日已签 / 今日目标，数字与弧线平滑补间，满签时金色祝贺文案
- **连续签到天数**：全局连续 + 单站连续 + 最长连续；当天未签不算断（避免「一觉醒来连续 0 天」）
- **历史热力图**：按周对齐、4 / 13 / 26 周可切换，强度按「当天目标快照」计算，增删站点不会改写历史格子
- **每日待办**：按天归属的清单，支持新增 / 勾选 / 编辑 / 删除 / 撤销 / 顺延昨天未完成项
- **一键打开未签到**：今天还没签、没暂停的站点分批在新标签页打开（每次最多 5 个），被浏览器拦截时提示放行
- **站点管理**：页面内增删改、分类筛选、搜索、置顶、暂停站点；按钮移位（按可见列表算邻居）+ 拖拽排序
- **浏览器书签导入**：解析 Chrome / Edge 导出的 HTML，按文件夹勾选导入，按 URL 去重
- **备份与恢复**：导出 / 导入带版本号的 JSON，合并取并集，兼容 v1 起的全部历史版本
- **数据保护模式**：检测到真正读不回来的数据时停止写入，允许下载原始内容后再恢复
- **孤儿记录清理**：已删站点留下的历史默认保留（重新添加可接回），需要时由用户手动清理
- **主题与动效**：深色 / 亮色外观、跟随时段的自动配色、指针跟随高光、紧凑模式、`prefers-reduced-motion` 适配
- **樱花装饰**：背景固定种子生成的樱花树 + 前景飘落花瓣，满签时触发一次爆发动画

### 电子日记

- **按天记录、一天多条**：上午的会议、下午的实习日志、晚上的随笔各记一条，标题可选、正文必填
- **翻历史**：前一天 / 后一天 / 日期选择 / 最近有日记的日子快捷跳转；可以补写过去，不能写未来
- **全文搜索**：按标题和正文搜，大小写不敏感，结果按日期从新到旧，点结果跳到那一天
- **自动保存**：编辑时停笔约 600 ms 或点到别处就保存，保存失败不清草稿、可重试；删除可撤销
- **离开提醒**：只在真的有未保存内容时才提醒——关页 / 刷新弹浏览器自带的确认，切到其他页面弹确认框；已经保存了就不打扰
- **只是记录**：不参与签到进度环，也不触发樱花满开

## 项目亮点与技术取舍

1. **站点身份由域名派生，保证历史永不丢失。** `site.id` 从 URL 域名生成（`https://www.jd.com` → `jd-com`），而不是从用户可改的名字派生。于是「删掉再加」同一个站会自动接回历史记录，域名重复也天然等价于站点重复。这条约束贯穿手动添加、书签导入、迁移三处，统一调用同一个 `siteIdFromUrl`。

2. **数据格式从 v1 演进到 v7，老数据和老备份都能自动升级。** 改结构的版本（如 v2→v3 把站点 id 改成域名派生、同步重写全部历史记录）写成顺序梯子，每档只还原「那一版当时的样子」；只加字段的版本（v4 待办、v5 目标快照、v6 明暗外观、v7 日记）不占梯子档位，在末尾统一清洗兜底。`storage.ts` 与 `backup.ts` 调用同一个 `migrate()`，避免「本机老数据能升级、导入老备份却报错」的割裂。跳级迁移会让后续映射表认不出旧 id，导致 v1 用户历史静默归零——这个坑有专门的链式测试守着。每加一个字段，备份合并 `mergeData` 也必须同步合并它，否则在新设备导入备份后数据会静默消失。

3. **保护模式的判据是 `droppedEntries`，不是长度差。** 只有「真的读不回来」的条目才触发只读停写；无害的去重（如重复 id）不算丢弃。判据一宽，用户就会被锁死在一份其实没坏的数据上。

4. **玻璃拟态的性能边界。** 核心视觉是 `backdrop-filter` 模糊 + 内阴影高光 + 指针跟随高光，全部手写 CSS。刻意避开会让元素成为独立 backdrop root 的 `contain: paint` / 祖先 `filter`；移动端主动降级模糊；会动的装饰层（花瓣）放前景走纯合成层，静止/慢摆的樱花树放背景，避免每帧重新模糊卡片背后的像素。

5. **樱花树的确定性与分形正确性。** 递归分形 + 固定种子伪随机（mulberry32），同一种子必生成同一棵树——勾选签到触发的重渲染不会让树在眼皮底下变形，同时让生成逻辑成为可单测的纯函数。递归角度边界必须用**反射**而非截断，否则边界成为吸引子，整棵树会退化成一把平行扫帚。

6. **工具箱严格分层：纯逻辑进 `lib/`，组件只做渲染。** `lib/` 不允许 `import React`，所有可测逻辑（切图矩形、压缩尺寸、裁剪几何、水印坐标、PDF 结构、条形码编码、单位换算、自然日差）都是纯函数并有单测；Canvas 绘制留在组件层。随机抽签的随机源可注入，洗牌用 Fisher-Yates 而非 `sort(() => random() - 0.5)`。

7. **手写最小 PDF 1.4 与 Code 128 编码。** 图片转 PDF 自己拼 PDF 结构，JPEG 用 DCTDecode 直嵌不二次压缩，xref 偏移经单测验证可被解析；条形码按 Code 128 Code Set B 的码表、校验和与 START/STOP 规则自行编码，不依赖第三方库。

8. **时区无关的自然日差。** 倒计时 / 纪念日把纯日期折成 UTC 天序号相减，而不是时间戳除 `86400000`——后者在夏令时那天只有 23/25 小时，四舍五入会随季节偏一天。

9. **长文本不逐字写盘。** 每次写操作都会把整份数据序列化后写进 localStorage，日记若在每次按键时保存，打字会随日记变多越来越卡。所以草稿只存在组件内存里，停笔约 600 ms 或失焦才提交一次（连续 5 次输入实测只落盘 1 次）。草稿只在「开始编辑」那一刻从数据初始化：页面在窗口重新获得焦点时会重读存储，草稿若跟着数据走，切个窗口回来没保存的字就被旧内容顶掉了。

10. **离开提醒按需出现，新页面自动受保护。** 有草稿的组件通过 `useLeaveGuard` 自己登记「我有未保存内容」；切页面只有一个入口 `navigate()`，它只问「有没有人登记」，不关心从哪页去哪页，所以以后新加的页面不用改任何代码就带上确认。关页提醒的 `beforeunload` 监听只在有未保存内容时挂上、保存后立刻摘掉：一直挂着会让浏览器不缓存页面（后退变成整页重载），而且每次正常关页都弹，用户很快就会无视它。编辑已有日记时正常切走不弹（卸载时会补存），只有保存失败过才拦。

## 目录结构

```
checkin-dashboard/
├─ src/
│  ├─ data/          静态配置（站点种子、工具箱目录、精选网页）
│  ├─ types.ts       数据契约（全局类型 + 当前 DATA_VERSION = 7）
│  ├─ hooks/         自定义 hooks（存储、今天、配色、指针光、补间、离开提醒等）
│  ├─ lib/           纯函数（不 import React，全部可单测）+ 同名 *.test.ts
│  ├─ components/    React 组件；Diary* 为日记视图，toolbox/ 为工具箱视图与各工具
│  └─ styles/        tokens / global / app / features / dashboard / sakura / toolbox / diary，工具专属样式在 styles/tools/
├─ scripts/          浏览器回归与专项验收脚本 *-check.mjs（CDP 驱动，零额外依赖）
├─ fixtures/         人工验收样本（书签 HTML），不参与构建
├─ .github/workflows/deploy.yml   GitHub Pages 自动部署
├─ vite.config.ts    base: './'（相对路径，兼容用户站与项目站）
└─ PROGRESS.md / MY-ISSUES.md / CLAUDE.md   进度、踩坑与项目规范
```

`lib/` 是项目的重心：日期换算、localStorage 读写、版本迁移、写操作 reducer、备份合并、连续天数、热力图、站点筛选排序、书签解析计划、樱花生成、日记（创建 / 排序 / 搜索 / 未保存判定），以及工具箱的全部纯逻辑都集中在这里。

## 部署

推送到 `master` 分支即由 `.github/workflows/deploy.yml` 自动构建并发布到 GitHub Pages：

1. `npm ci`（严格按 lock 文件安装）
2. `npm test`（单测必须全绿）
3. `npm run build`（先 `tsc --noEmit`，类型有错即中断）
4. 上传 `dist/` 并通过 `deploy-pages` 发布

`vite.config.ts` 使用 `base: './'`，产物可部署在域名任意层级，避免「用户站 / 项目站」base 配错导致的白屏 404。

## 已知边界

- 纯静态站无法做定时推送，也无法实现需要后端存储的功能（如临时分享箱）。
- 数据仅存本机 localStorage，不跨设备同步；不同网址（如本地开发地址和线上地址）各存一份，互相看不到，换设备只能靠导出 / 导入备份。
- 日记只支持纯文本，不存图片：localStorage 每个网址约 5 MB，图片几张就会写满配额，之后所有保存（包括签到）都会失败。
- 同域名只能有一张签到卡片（身份即域名）；已删除站点的历史记录会保留为孤儿记录，以便重新添加时恢复。
- 证件照换背景基于颜色接近度，只适合背景干净均匀的照片，不做发丝级抠图。
